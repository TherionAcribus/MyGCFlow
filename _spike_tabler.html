Points d'attention détectés

  • Colorpicker : Tabler n'en fournit aucun. vanilla-colorful est un bon remplaçant (léger, accessible, sans dépendance), mais il faudra recréer la palette de couleurs prédéfinies du fork Materialize.
  • Sliders avancés : les input[type=range] natifs suffisent pour l'opacité/vitesse, mais si l'app utilise des ticks/pips ou des sliders à deux poignées, noUiSlider sera nécessaire.
  • Effet ripple (waves-effect) : absent de Tabler. Si cet effet est jugé important pour l'UX, intégrer la lib Waves (~3 KB).
  • Toasts : pas d'API globale M.toast() ; il faut instancier bootstrap.Toast et gérer le conteneur d'empilement.
  • Chips dynamiques (input) : Tabler n'a pas de « chip input » ; à recréer ou utiliser Tom Select en mode tags.
  • Material Icons : indépendants de Materialize, donc conservables sans risque.
  • Bundle JS : tabler.min.js inclut déjà Bootstrap 5 ; ne pas recharger un bundle Bootstrap séparé (risque de double initialisation des composants).

Recommandation finale

Tabler couvre la quasi-totalité des besoins fonctionnels de GCMap. Les composants structurels (tabs, modals, cards, dropdowns, accordions, switches, selects, tooltips, toasts, dark mode) sont disponibles nativement. Les seuls écarts nécessitant une lib tierce sont le colorpicker (vanilla-colorful) et,optionnellement, les sliders avancés (noUiSlider) et l'effet ripple (Waves).

Risques résiduels :

  • Refonte CSS du theme.css actuel vers les variables Tabler (--tblr-*).
  • Recréation de la control-bar latérale (pas de composant dédié).
  • Migration du fork materialize-colorpicker (palette + API) vers vanilla-colorful.
  • Réécriture des appels JS Materialize (M.modal, M.toast, M.tabs, etc.) vers les API Bootstrap/Tabler.

Verdict : migration faisable, effort modéré, dépendances tierces minimales et bien identifiées.
